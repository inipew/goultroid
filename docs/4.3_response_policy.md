# GoUltroid 4.3 — Response Policy

## Tujuan

Response normal untuk incoming `.command` harus menggunakan:

```text
Reply → optional auto-delete trigger
```

Bukan:

```text
Edit incoming command → fallback Reply
```

`Edit` tetap dipakai untuk message yang dimiliki userbot, terutama progress/multi-stage response.

## Contract

```text
Incoming command + Respond
    → SendMessage
    → optionally Delete trigger (best effort)

Bot-owned response + EditOrReply
    → Edit existing bot response

Reply → EditOrReply
    → Edit LastResponseID
```

## Implementasi

`MessagesFacade.EditOrReply()` harus mempertahankan semantic ownership check:

```go
if LastResponseID != 0 {
    return Edit()
}
if Message != nil && Message.IsOutgoing {
    return Edit()
}
return Reply()
```

Higher-level `Respond()`/`ReplyAndDelete()` menjadi API yang dipakai command normal ketika trigger memang harus dibersihkan.

Delete adalah cleanup best-effort: kegagalan delete tidak boleh membuat command yang reply-nya sukses dianggap gagal.

## Target

1. Tidak ada failed `EditMessage` untuk incoming command.
2. `.command` dapat dihapus setelah response sukses.
3. Response tampil sebelum cleanup trigger.
4. Existing bot response tetap editable.
5. Tidak ada plugin yang perlu menebak ownership message.
6. Response behavior dapat diukur melalui telemetry.

## Performance invariant

Normal incoming command harus mempunyai satu intentional response RPC:

```text
SendMessage
```

dan satu cleanup RPC hanya bila policy `DeleteTrigger=true`:

```text
DeleteMessages
```

Tidak boleh ada:

```text
EditMessage(fail) → SendMessage
```

## Implementasi lanjutan

Semua plugin yang saat ini memakai `EditOrReply()` sebagai response pertama perlu dimigrasikan secara bertahap ke `Respond()`/`ReplyAndDelete()` setelah API tersebut tersedia, dengan pengecualian workflow yang memang membutuhkan editing message.
