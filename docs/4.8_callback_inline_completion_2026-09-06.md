## 1. Executive Summary

Following the comprehensive audit in `4.6_callback_inline_implementation_audit_2026-09-06.md`, the Callback and Inline subsystem of GoUltroid was upgraded from an initial baseline into a production-grade, extensible, and secure interaction layer.

Semantics and security gaps identified during the audit—such as inline message edit targeting, single source of truth for callback target origins, fail-closed authorization on chat IDs, interactive button cache leakage, max 50 hard limits, and typed multi-media inline serialization—have been completely resolved.

## 2. Completed Scope & Architecture

### 2.1 Callback Engine Hardening (Tahap 1)

1. **RPC Answer Error Semantics:**
   - In `internal/services/callback/types.go`, `CallbackContext.Answer()` sets `c.answered = true` strictly upon successful RPC execution (`err == nil`). If an error (e.g. FloodWait or RPC timeout) occurs, callers and fallback mechanisms can retry without false assumptions.

2. **Preservation of Original Text on Markup Mutation (`EditMarkup`):**
   - MTProto exposes flags for message edits. `req.SetMessage("")` strips text, whereas setting only `req.SetReplyMarkup(markup)` updates inline keyboard buttons while preserving the original message text.
   - Added `EditMessageMarkupOnly` and `EditInlineBotMessageMarkup` to `TelegramServicer` ([`internal/core/context.go`](file:///home/dhimas/any/random/ultroid-go/internal/core/context.go), [`internal/telegram/service.go`](file:///home/dhimas/any/random/ultroid-go/internal/telegram/service.go), [`internal/core/mock.go`](file:///home/dhimas/any/random/ultroid-go/internal/core/mock.go)).
   - `CallbackContext.EditMarkup()` dynamically dispatches to `EditInlineBotMessageMarkup` for inline targets and `EditMessageMarkupOnly` for chat targets.

3. **Unified `CallbackTarget`:**
   - Method `CallbackTarget.IsInline()` was established as the single source of truth for checking if a callback originates from an inline message (`Origin == CallbackOriginInline || InlineID != nil`).
   - `CallbackQueryEvent.IsInline()` and `CallbackContext.IsInline()` delegate directly to `Target.IsInline()`.

### 2.2 Inline Engine & Security Hardening (Tahap 1)

1. **Fail-Closed Chat Authorization & `AllowedChatTypes`:**
   - Telegram MTProto `updateBotInlineQuery` does not disclose the destination chat ID to the bot. Handlers configured with `AllowedChats` therefore fail-closed in inline mode to prevent data leaks.
   - Added support for `AllowedChatTypes` (`ChatTypePrivate`, `ChatTypeGroup`, `ChatTypeSupergroup`, `ChatTypeChannel`). Telegram provides `update.PeerType`, which is forwarded via `Dispatcher.OnBotInlineQuery` -> `Engine.ExecuteWithPeerType`.

2. **Interactive Button Cache Leakage Protection:**
   - If inline results contain interactive callback buttons (`ButtonCallback` or non-empty callback data), `CacheGlobal` is automatically downgraded to `CachePerUser`. This ensures one user's state payload cannot be hijacked or reused by another user in a shared chat.
   - The engine performs scoped cache lookup with fallback from `CacheGlobal` to `CachePerUser`.

3. **Hard Invariant: Max 50 Results:**
   - Telegram MTProto strictly caps `messages.setInlineBotResults` to 50 results. Truncation is enforced on handler output, pagination output, cache hits, and serialization.
   - Added `Engine.SetPaginator(p *Paginator)` to allow configuring pagination parameters.

### 2.3 Modular Typed Serializers (Tahap 2)

1. **`ResultSerializer` & `SerializerRegistry` ([`internal/services/inline/serializer.go`](file:///home/dhimas/any/random/ultroid-go/internal/services/inline/serializer.go)):**
   - Replaced monolithic serialization with modular serializers per `InlineResultType`:
     - `ResultArticle`: `InputBotInlineResult` with `InputBotInlineMessageText`.
     - `ResultPhoto`: `InputBotInlineResult` with `InputWebDocument` and `InputBotInlineMessageMediaAuto` (when `MediaURL` present) or `InputBotInlineMessageText`.
     - `ResultDocument`, `ResultVideo`, `ResultGif`, `ResultAudio`: Sets MIME types and auto-delivers media via `InputBotInlineMessageMediaAuto`.
     - `ResultGeo`: `InputBotInlineMessageMediaGeo` with `InputGeoPoint`.
     - `ResultVenue`: `InputBotInlineMessageMediaVenue` with coordinates, title, and address.
     - `ResultContact`: `InputBotInlineMessageMediaContact` with phone number and vCard.
     - `ResultGame`: `InputBotInlineResultGame` with `ShortName` and `InputBotInlineMessageGame`.

2. **HTML Entity Parsing:**
   - `parseFormattedText()` utilizes gotd `html.HTML` parser and `entity.Builder` to convert HTML strings (`<b>`, `<code>`, `<i>`, etc.) into true Telegram MTProto `[]tg.MessageEntityClass`, ensuring inline results render with bold/code styling rather than raw tags.

3. **Response Options Verification (`switch_pm` & `switch_webview`):**
   - `opts.SwitchPM` (`tg.InlineBotSwitchPM`) and `opts.SwitchWebView` (`tg.InlineBotWebView`) are verified to correctly propagate through `Engine` and `TelegramServicer` with proper MTProto flag bit computation (`SetFlags()`).
   - Private results automatically disable server-side caching (`CacheTime = 0`).
